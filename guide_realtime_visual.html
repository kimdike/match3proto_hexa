1. 헥사 그리드 구조

게임 보드는 9-8-9-8-9-8-9-8-9 패턴의 벌집형 헥사 그리드입니다.

총 77셀. 각 셀은 6방향 인접 (좌상/우상/좌/우/좌하/우하).

일반 (normal)
입구 (entrance)
죽은 셀 (dead)
통과 (pass)

2. 셀 타입 4종

🟢 entrance (입구) — 블록 생성

맨 위에 배치. 아래 빈 셀로 새 블록을 떨어뜨림. 보드 안에도 임의 위치 배치 가능.

⚫ normal — 일반 셀

블록이 머무는 자리. 중력 영향. 매칭 대상.

🔴 dead — 죽은 셀 (장벽)

블록 통과 불가. 위→아래 충전 차단. 그 아래 빈 셀은 대각선에서만 채워짐.

🟣 pass — 통과 셀

블록이 머물지 않고 투명 통과. 충전 경로 계산 시 건너뜀.

3. 핵심 — 두 정보 층 (Data + Visual)

게임은 같은 셀에 대해 2개의 정보 층을 동시에 관리합니다.

📊 board (데이터 층)
🎨 blockEls (시각 층)

📊 board (데이터 층) — 진실의 원천

board[col][row] = { color: 빨강, type: 'normal' }

"이 셀에 빨간 블록이 있어야 한다"는 게임 상태 기록.

🎨 blockEls (시각 층) — 실제 화면

blockEls[col][row] = <빨간 원 DOM element>

화면에 실제로 보이는 빨간 원의 reference.

⚠️ 이 두 층의 불일치가 게임의 모든 race 버그의 원천입니다.

4. swap 동작 — Atomic 처리 (Phase 2)

사용자가 두 인접 블록을 swap할 때:

1이전 (race 발생)

  • swap 시작 시점: el1, el2 reference 잡음
  • CSS transition 0.22초 시작 (위치 swap 시각 효과)
  • 0.22초 후: blockEls swap. 그 사이 다른 흐름이 끼어들면 충돌

2이후 (atomic, race 0)

  • swap 시작 시점: el1, el2 reference 잡음
  • 즉시 blockEls + dataset swap (sync)
  • CSS transition 0.22초 시각 효과만 진행
  • 다른 흐름이 보는 blockEls는 이미 swap 상태 → 충돌 없음

✅ 비유 — 엘리베이터를 옆 건물로 옮기는 작업

이전: "옮길게~" 예약 → 나중에 실제 처리

이후: "옮긴 걸로 친다!" 즉시 장부 기록 → 시각만 천천히

5. 매치 + 충전 (Ticker 모델)

매치 처리는 ticker라는 백그라운드 시스템이 담당합니다.

1매치 감지 + 제거

  • board[c][r] = null (데이터 즉시 분리)
  • blockEls[c][r] = null (시각 reference 즉시 분리)
  • element는 matched class로 fade-out 진행 (0.28s)
  • animationend 이벤트로 자동 detach

2중력 (Gravity)

위쪽 블록이 아래 빈 셀로 떨어짐.

3충전 (Fill)

entrance에서 새 블록 생성해 빈 셀로 떨어뜨림.

4Ticker — 백그라운드 진행

매 50ms마다 ticker가 보드 검사:

tick 1 (0ms) — gravity 1단계 tick 2 (50ms) — fill 1단계 tick 3 (100ms) — gravity 2단계 ...

매치 처리/특수효과 진행 중에도 충전이 백그라운드에서 동시 진행. 흐름 끊김 없음.

6. ZOMBIE-RECOVER 안전망

어떤 race 상황이 발생해 데이터는 있는데 시각만 사라진 상태:

⚠️ ZOMBIE 상태

board[2][7] = { color: 빨강, type: normal } ← 데이터 있음

blockEls[2][7] = null ← 시각만 사라짐

→ 화면에서는 빈 셀로 보임

Ticker의 자동 복구

매 50ms 검사 → ZOMBIE 발견 → board에 기록된 색/타입 그대로 새 element 생성:

✅ 중요: 랜덤 새 블록이 아니라 같은 색의 같은 블록이 같은 자리에 다시 그려짐.

게임 진행에 영향 X (점수/매치/콤보 무관). 시각만 동기화.

7. 종합 — 실시간 매칭이 가능한 이유

4가지 메커니즘이 동시 작동

  • ① swap atomic — swap 220ms race 차단
  • ② animationend detach — 매치 200ms race 차단
  • ③ ZOMBIE-RECOVER — 시각 안전망 (빈 셀)
  • ④ DOM-DUP-CLEAR — 시각 안전망 (블록 겹침)

✅ 결과: 두 swap이 동시 진행되어도 race 발생 시점 자체가 거의 0. 발생하더라도 ticker 안전망이 자동 복구.

사용자 체감: 두 매치가 시각적으로 겹쳐 동시 진행 + 끊김 없는 충전.
